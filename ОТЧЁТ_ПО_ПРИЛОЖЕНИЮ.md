# Отчёт по приложению для управления школьными классами

## 1. Анализ предметной области и формирование требований к веб-приложению

### 1.1. Предметная область

Приложение предназначено для организации коммуникации между администраторами школьных классов (учителями), модераторами и родителями учащихся через платформу Telegram и веб-интерфейс. Система позволяет:

- Управлять школьными классами
- Создавать и публиковать новости для родителей
- Загружать и распространять отчёты (документы)
- Управлять процессом верификации родителей
- Управлять правами доступа (администраторы, модераторы, родители)

### 1.2. Целевая аудитория

- **Администраторы классов** (учителя): могут создавать классы (до 10 шт.), публиковать новости, загружать отчёты, управлять модераторами и верифицировать родителей
- **Модераторы**: могут публиковать новости и отчёты, верифицировать родителей в назначенных классах
- **Родители**: могут просматривать новости и скачивать отчёты после верификации

### 1.3. Функциональные требования

#### 1.3.1. Управление пользователями и ролями
- Регистрация пользователей через Telegram
- Система ролей: Admin, Moderator, Parent, Unverified
- Верификация родителей администраторами/модераторами
- Связь одного родителя с несколькими классами (для родителей с несколькими детьми)

#### 1.3.2. Управление классами
- Создание класса администратором (до 10 классов на одного админа)
- Удаление класса
- Назначение модераторов на класс
- Просмотр списка родителей класса

#### 1.3.3. Управление контентом
- Создание новостей с заголовком и текстом
- Создание отчётов с прикреплением файлов
- Редактирование и удаление новостей
- Публикация новостей через очередь сообщений (RabbitMQ)
- Хранение файлов отчётов в объектном хранилище (MinIO)

#### 1.3.4. Веб-интерфейс
- Аутентификация администраторов и модераторов через Telegram User ID
- Просмотр и управление новостями через веб-панель
- Управление заявками на верификацию
- Просмотр списка родителей и модераторов

#### 1.3.5. Telegram-бот
- Команды для всех типов пользователей
- Интерактивные меню и кнопки
- Пагинация при просмотре новостей и отчётов
- Скачивание отчётов через бота

### 1.4. Нефункциональные требования

- **Производительность**: асинхронная обработка новостей через очередь сообщений
- **Масштабируемость**: использование микросервисной архитектуры (очереди, объектное хранилище)
- **Безопасность**: аутентификация через Cookie Authentication, контроль доступа по ролям
- **Надёжность**: автоматическое применение миграций БД при старте, retry-логика для подключений
- **Развёртывание**: контейнеризация через Docker Compose

## 2. Проектирование архитектуры веб-приложения

### 2.1. Архитектурный подход

Приложение построено на основе **многослойной архитектуры (Layered Architecture)** с элементами **микросервисной архитектуры** для обработки асинхронных задач.

### 2.2. Основные компоненты

#### 2.2.1. Веб-приложение (ASP.NET Core MVC)
- **Слой представления (Views)**: Razor Pages для веб-интерфейса
  - `Views/Home/Index.cshtml` - главная страница с новостями
  - `Views/News/Create.cshtml`, `Edit.cshtml` - управление новостями
  - `Views/Verifications/Index.cshtml` - управление заявками на верификацию
  - `Views/Parents/Index.cshtml` - список родителей
  - `Views/Moderators/Index.cshtml` - список модераторов
  - `Views/Account/Login.cshtml` - страница входа

- **Слой контроллеров (Controllers)**:
  - `HomeController` - главная страница
  - `NewsController` - управление новостями и отчётами (CRUD операции)
  - `AccountController` - аутентификация и авторизация
  - `VerificationsController` - обработка заявок на верификацию
  - `ParentsController` - управление списком родителей
  - `ModeratorsController` - управление модераторами

- **Слой бизнес-логики (Services)**:
  - `TelegramBotService` - фоновый сервис для обработки обновлений Telegram
  - `NewsQueueProducer` - публикация новостей в очередь
  - `NewsQueueConsumer` - фоновый сервис для обработки очереди новостей
  - `RabbitMqService` - работа с RabbitMQ
  - `MinioService` - работа с объектным хранилищем MinIO (S3-совместимое)
  - `NotificationService` - отправка уведомлений
  - `EnvService` - управление переменными окружения

- **Слой доступа к данным (Persistence)**:
  - `ApplicationDbContext` - контекст Entity Framework Core
  - Миграции базы данных (4 миграции)

#### 2.2.2. Telegram Bot Service
- Фоновый сервис (`TelegramBotService`) для обработки обновлений от Telegram API
- Обработчики команд и сообщений (`UpdateHandler`, `Handlers/*.cs`)
- Интеграция с базой данных через Dependency Injection

#### 2.2.3. Очередь сообщений (RabbitMQ)
- Асинхронная обработка публикации новостей
- Producer-Consumer паттерн для распределения нагрузки
- Обеспечивает отказоустойчивость при отправке сообщений

#### 2.2.4. Объектное хранилище (MinIO)
- Хранение файлов отчётов
- S3-совместимое API
- Генерация предварительно подписанных URL для безопасной загрузки

### 2.3. Технологический стек

- **Backend Framework**: ASP.NET Core 8.0 (MVC)
- **База данных**: PostgreSQL
- **ORM**: Entity Framework Core 8.0.11
- **Telegram API**: Telegram.Bot 19.0.0
- **Очередь сообщений**: RabbitMQ 3-management
- **Объектное хранилище**: MinIO 6.0.2
- **Контейнеризация**: Docker, Docker Compose
- **Язык программирования**: C# (.NET 8.0)

### 2.4. Паттерны проектирования

- **Repository Pattern**: интерфейс `IS3Repository` для работы с хранилищем
- **Dependency Injection**: встроенный DI контейнер ASP.NET Core
- **Background Services**: для обработки очередей и Telegram обновлений
- **Service Layer Pattern**: бизнес-логика вынесена в сервисы
- **MVC Pattern**: разделение представления, контроллера и модели

## 3. Проектирование базы данных приложения

### 3.1. Выбор СУБД

Используется **PostgreSQL** как реляционная СУБД, обеспечивающая:
- Надёжность и ACID-совместимость
- Поддержку сложных запросов и связей
- Масштабируемость
- Интеграцию с Entity Framework Core

### 3.2. Структура базы данных

База данных включает 5 основных таблиц:

#### 3.2.1. Таблица `Users`
Хранит информацию о пользователях системы.

**Поля:**
- `Id` (bigint, PK) - уникальный идентификатор
- `TelegramUserId` (bigint, UNIQUE, NOT NULL) - ID пользователя в Telegram
- `Username` (string, nullable) - имя пользователя в Telegram
- `FirstName` (string, nullable) - имя
- `LastName` (string, nullable) - фамилия
- `Role` (enum → string) - роль пользователя (Admin, Moderator, Parent, Unverified)
- `ClassId` (int, nullable, FK → Classes.Id) - текущий класс пользователя
- `IsVerified` (bool) - статус верификации
- `FullName` (string, nullable) - полное ФИО
- `PhoneNumber` (string, nullable) - номер телефона
- `CreatedAt` (DateTime) - дата создания
- `VerifiedAt` (DateTime, nullable) - дата верификации

**Индексы:**
- Уникальный индекс на `TelegramUserId`

**Связи:**
- Многие-к-одному с `Classes` через `ClassId` (ON DELETE RESTRICT)

#### 3.2.2. Таблица `Classes`
Хранит информацию о школьных классах.

**Поля:**
- `Id` (int, PK) - уникальный идентификатор
- `Name` (string, NOT NULL) - название класса (например, "5А", "10Б")
- `AdminTelegramUserId` (bigint, FK → Users.TelegramUserId) - Telegram ID администратора
- `CreatedAt` (DateTime) - дата создания

**Связи:**
- Один-ко-многим с `Users` (администратор) через `AdminTelegramUserId` (ON DELETE RESTRICT)
- Один-ко-многим с `News` через `ClassId` (ON DELETE CASCADE)
- Один-ко-многим с `ParentClassLinks` через `ClassId` (ON DELETE CASCADE)

#### 3.2.3. Таблица `News`
Хранит новости и отчёты классов.

**Поля:**
- `Id` (int, PK) - уникальный идентификатор
- `ClassId` (int, FK → Classes.Id, NOT NULL) - ID класса
- `AuthorTelegramUserId` (bigint) - Telegram ID автора
- `Title` (string, NOT NULL) - заголовок
- `Content` (string, NOT NULL) - содержимое (может быть пустым для отчётов)
- `Type` (enum → string) - тип записи (News или Report)
- `FilePath` (string, nullable) - путь к файлу в объектном хранилище (для отчётов)
- `FileName` (string, nullable) - оригинальное имя файла
- `CreatedAt` (DateTime) - дата создания

**Связи:**
- Многие-к-одному с `Classes` через `ClassId` (ON DELETE CASCADE)

#### 3.2.4. Таблица `ParentVerifications`
Хранит заявки на верификацию родителей.

**Поля:**
- `Id` (int, PK) - уникальный идентификатор
- `TelegramUserId` (bigint, NOT NULL) - Telegram ID родителя
- `FullName` (string, NOT NULL) - ФИО
- `PhoneNumber` (string, NOT NULL) - номер телефона
- `Status` (enum → string) - статус (Pending, Approved, Rejected)
- `ClassId` (int, nullable) - ID класса, к которому относится заявка
- `CreatedAt` (DateTime) - дата создания заявки
- `ProcessedAt` (DateTime, nullable) - дата обработки
- `ProcessedByTelegramUserId` (bigint, nullable) - Telegram ID модератора/админа, обработавшего заявку

#### 3.2.5. Таблица `ParentClassLinks`
Связь многие-ко-многим между родителями и классами (для родителей с несколькими детьми).

**Поля:**
- `Id` (int, PK) - уникальный идентификатор
- `UserId` (bigint, FK → Users.Id, NOT NULL) - ID пользователя (родителя)
- `ClassId` (int, FK → Classes.Id, NOT NULL) - ID класса
- `CreatedAt` (DateTime) - дата создания связи

**Индексы:**
- Составной уникальный индекс на (`UserId`, `ClassId`)

**Связи:**
- Многие-к-одному с `Users` через `UserId` (ON DELETE CASCADE)
- Многие-к-одному с `Classes` через `ClassId` (ON DELETE CASCADE)

### 3.3. Миграции базы данных

Система использует **Entity Framework Core Migrations** для управления схемой БД:

1. **InitialCreate** (2025-12-05) - начальная структура БД (Users, Classes, News, ParentVerifications)
2. **AddParentClassLinks** (2025-12-09) - добавление таблицы ParentClassLinks для связи многие-ко-многим
3. **AllowMultipleClassesPerAdmin** (2025-12-09) - изменение связей для поддержки нескольких классов на одного админа
4. **AddNewsFileFields** (2025-12-17) - добавление полей FilePath и FileName для хранения файлов отчётов

### 3.4. Нормализация базы данных

База данных соответствует 3NF (третьей нормальной форме):
- Все неключевые атрибуты зависят только от первичного ключа
- Нет транзитивных зависимостей
- Отсутствует избыточность данных

### 3.5. Целостность данных

- **Внешние ключи**: обеспечивают ссылочную целостность
- **Cascade Delete**: при удалении класса автоматически удаляются связанные новости и связи с родителями
- **Restrict Delete**: предотвращает удаление пользователя, если он является администратором класса
- **Уникальные ограничения**: предотвращают дублирование записей (TelegramUserId, комбинация UserId+ClassId)

## 4. Реализация Backend и UI частей веб-приложения

### 4.1. Backend-реализация

#### 4.1.1. Конфигурация приложения (`Program.cs`)

Приложение настраивается через `Program.cs` с использованием минимальных API:

**Основные компоненты:**
- Регистрация сервисов (Controllers, Views, DbContext)
- Настройка аутентификации через Cookie Authentication
- Настройка подключения к PostgreSQL
- Регистрация Telegram Bot Client
- Настройка RabbitMQ с retry-логикой
- Настройка MinIO/S3 репозитория
- Регистрация фоновых сервисов (TelegramBotService, NewsQueueConsumer)
- Автоматическое применение миграций при старте приложения

**Ключевые особенности:**
- Retry-механизм для подключения к БД и RabbitMQ (10 попыток с задержкой 3 секунды)
- Graceful degradation: если миграции не применяются, используется `EnsureCreated()`

#### 4.1.2. Контроллеры

**HomeController:**
- `Index(int? classId)` - главная страница с списком новостей выбранного класса
- Авторизация только для Admin и Moderator
- Поддержка выбора класса через dropdown

**NewsController:**
- `Create()` (GET/POST) - создание новостей и отчётов
- `Edit(int id)` (GET/POST) - редактирование новостей
- `Delete(int id)` (POST) - удаление новостей
- Интеграция с MinIO для загрузки файлов отчётов
- Публикация новостей в RabbitMQ очередь
- Валидация прав доступа к классам

**AccountController:**
- `Login()` (GET/POST) - аутентификация через Telegram User ID
- `Logout()` (POST) - выход из системы
- Создание Claims на основе роли пользователя
- Cookie-аутентификация с сроком действия 30 дней

**VerificationsController:**
- `Index(int? classId)` - список заявок на верификацию
- `Approve(int id)` - одобрение заявки и создание связи ParentClassLink
- `Reject(int id)` - отклонение заявки

**ParentsController / ModeratorsController:**
- Управление списками родителей и модераторов классов

#### 4.1.3. Сервисы

**TelegramBotService:**
- Background Service для обработки обновлений Telegram
- Использует Long Polling через `StartReceiving`
- Создаёт scope для каждого обновления (scoped DbContext)
- Обработка ошибок с логированием

**NewsQueueProducer:**
- Публикация сообщений о новостях в RabbitMQ очередь
- Сериализация через JSON
- Thread-safe операции с использованием lock

**NewsQueueConsumer:**
- Background Service для обработки очереди новостей
- Асинхронная обработка сообщений
- Отправка новостей всем подписанным родителям, модераторам и администраторам класса
- Поддержка связи многие-ко-многим через ParentClassLinks

**MinioService:**
- Реализация интерфейса `IS3Repository`
- Автоматическое создание bucket при необходимости
- Загрузка файлов, получение потоков, удаление
- Генерация предварительно подписанных URL для безопасного доступа

**RabbitMqService:**
- Управление подключением и каналом RabbitMQ
- Объявление очереди

#### 4.1.4. Обработчики Telegram-бота

Модульная структура обработчиков в папке `Handlers/`:
- `StartHelpRegister.cs` - команды /start, /help, /register
- `Commands.cs` - другие команды бота
- `Callbacks.cs` - обработка callback-кнопок
- `News.cs` - управление новостями через бота
- `Verifications.cs` - управление верификациями
- `ParentsModerators.cs` - управление родителями и модераторами
- `State.cs` - управление состояниями пользователя (state machine)

### 4.2. UI-реализация

#### 4.2.1. Технологии

- **Razor Pages** - серверный рендеринг
- **Bootstrap 5** - фреймворк для стилизации (судя по классам в Views)
- **Bootstrap Icons** - иконки
- **Layout Template** (`_Layout.cshtml`) - общий шаблон страниц

#### 4.2.2. Основные страницы

- Обработка ошибок с выводом сообщений

**Index.cshtml (Home):**

- Dropdown для выбора класса
- Карточки новостей с различными бейджами для типа (новость/отчёт)
- Кнопки редактирования и удаления
- Кнопка создания новой новости

**Create.cshtml / Edit.cshtml (News):**
- Форма создания/редактирования новостей
- Выбор типа (новость/отчёт)

- Валидация на стороне клиента и сервера

**Index.cshtml (Verifications):**
- Таблица заявок на верификацию с фильтрацией по классу
- Кнопки одобрения и отклонения
- Отображение информации о заявителе (ФИО, телефон)

**Index.cshtml (Parents/Moderators):**
- Списки родителей/модераторов класса
- Возможность управления правами

#### 4.2.3. Общие элементы UI

**Layout (_Layout.cshtml):**
- Навигационное меню
- Общие стили и скрипты
- Поддержка Bootstrap

**ViewImports.cshtml:**
- Общие using-директивы для всех Views

**ViewStart.cshtml:**
- Установка Layout по умолчанию

### 4.3. Безопасность

#### 4.3.1. Аутентификация и авторизация

- **Cookie Authentication**: использование стандартной схемы ASP.NET Core
- **Authorization**: атрибут `[Authorize]` на контроллерах
- **Role-based access control**: проверка роли пользователя (Admin, Moderator)
- **Claims-based identity**: хранение роли и ClassId в claims

#### 4.3.2. Защита от атак

- **CSRF Protection**: `[ValidateAntiForgeryToken]` на POST-методах
- **SQL Injection**: использование параметризованных запросов через EF Core
- **XSS Protection**: автоматическое экранирование в Razor Views

### 4.4. Обработка ошибок

- Try-catch блоки в критических местах
- Логирование ошибок через `ILogger`
- Graceful degradation при недоступности внешних сервисов
- Retry-логика для подключений

### 4.5. Развёртывание

**Docker Compose конфигурация:**
- Сервис `tgschoolbot` - основное приложение
- Сервис `db` - PostgreSQL
- Сервис `rabbitmq` - RabbitMQ с веб-интерфейсом управления

### 6.3. Самооценка по проделанной работе

#### 6.3.1. Трудности, с которыми столкнулись

В процессе разработки проекта были преодолены следующие трудности:

**1. Интеграция нескольких внешних сервисов:**
- **Проблема:** Необходимо было интегрировать Telegram Bot API, RabbitMQ и MinIO, каждый со своими особенностями подключения и работы
- **Решение:** Изучена документация по каждому сервису, реализован retry-механизм для надёжного подключения, использован Dependency Injection для управления зависимостями

**2. Управление состояниями в Telegram-боте:**
- **Проблема:** Необходимо было реализовать многошаговые операции (регистрация, создание класса) с сохранением состояния пользователя
- **Решение:** Реализована система состояний на основе словаря в памяти с использованием паттерна State Machine

**3. Связь многие-ко-многим для родителей и классов:**
- **Проблема:** Требовалась поддержка ситуации, когда один родитель может быть привязан к нескольким классам
- **Решение:** Создана промежуточная таблица `ParentClassLinks` и соответствующая миграция, обновлена бизнес-логика для работы с несколькими классами

**4. Асинхронная обработка новостей:**
- **Проблема:** Необходимо было обеспечить надёжную отправку новостей всем подписчикам без блокировки основного потока
- **Решение:** Реализован Producer-Consumer паттерн с использованием RabbitMQ, создан фоновый сервис для обработки очереди

**5. Настройка Docker Compose:**
- **Проблема:** Требовалась правильная настройка зависимостей между сервисами и управление переменными окружения
- **Решение:** Изучена документация Docker Compose, настроены health checks и depends_on для правильной последовательности запуска сервисов
